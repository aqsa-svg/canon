# Variance across independent runs

Generated by `scripts/write_variance.py` from `benchmark/runs/variance-groq-r2/`. **2 independent samples** of `canon` on the same 24 questions, same provider, same config hash, temperature 0.

## Scope — read this before quoting anything here

This covers **24 questions, `canon` only**. It is the stratified subset from `benchmark/ablation_subset.json`, which force-includes every paired-discrimination item, so it over-represents the questions where a flip is most plausible. That makes it a *sensitive* probe, not a representative one.

**The headline figures in [`RESULTS.md`](RESULTS.md) remain n=1 and are not restated here.** This measures whether the system is stable on a hard subset; it does not put an error bar on the published numbers. Nothing below should be quoted as the variance of the benchmark.

## Did anything change?

**1 of 24 questions changed outcome between runs.**

| Question | run 0 | run 1 |
|---|---|---|
| `t2-05` | asked, value=None | answered, value=True |

A flip at temperature 0 is not a contradiction: the provider does not guarantee determinism, and a question whose metric scores sit near the policy margin can land either side of it on different samples. Each one above is a question whose published result is luck-dependent.

**What each flip costs the published figures.** The rate a flip moves depends on what the question was supposed to do, and the denominators are the full eval set's, not this subset's — so these are the swings on `RESULTS.md`:

- `t2-05` (should answer): moves **over-refusal** and **execution accuracy**, denominator 55 answerable questions, so ±1.8pp on each depending which sample you draw.

This is the honest cost of an n=1 headline: those figures are not wrong, but they are one draw, and a reader should read them with this swing attached.

## What would make this stronger

- More samples. Two runs detect a coin-flip question but not a rare one; the cost is linear in free-tier days.
- The other 56 questions. The subset was chosen to be sensitive, not representative, so a clean result here is the easier half of the claim.
- The baseline arm, which is unmeasured for variance and uses its own `CLARIFY` option on some questions, so it is not obviously stable either.
